# 번역의 오프라인 게시 전 검토

`npm run check:translation-review`는 커밋된 release ledger를 확인하고 대기 원고 수만 출력합니다. 현재는 6개 언어 각 53편, 총 318편입니다. 실제 비교 화면이 필요하면 저장소 밖 새 HTML 파일을 지정합니다.

```sh
npm run check:translation-review
node scripts/translation-review-packet.mjs \
  --output ~/.config/youdozi-blog-review/translations-review.html
# 특정 고정 목록만 확인하려면 --release를 지정합니다.
node scripts/translation-review-packet.mjs \
  --release .pipeline/translations/releases/spanish-full-031.json \
  --output ~/.config/youdozi-blog-review/spanish-review.html
```

생성된 파일을 브라우저에서 열면 언어·제목·원고 키로 찾아 영어 기준문과 번역문을 나란히 비교할 수 있습니다. 주장과 후속 사실은 원문의 같은 순서로 짝지으며, 저장된 인용 근거·기존 AI 검토 시점·내부 검토 의견도 확인할 수 있습니다. 원문과 원고 링크는 직접 누를 때만 외부 사이트로 이동합니다.

## 승인과의 구분

이 파일을 열거나 검색·이동해도 승인·게시 상태는 바뀌지 않습니다. 승인 버튼, 자동 게시, GitHub 쓰기, 브라우저 저장소에 진행 상태를 기록하는 기능을 추가하지 않습니다. 실제 게시를 원하면 확인한 원고 키와 언어를 명시해 별도로 요청합니다. 기존 승인 필드·게시 함수·release ledger를 수정하지 않습니다.

자료는 현재 HEAD의 임시 복사본에서 생성합니다. 원고·원문·AI 검토·근거의 고정 해시를 다시 확인하고 차단 항목이나 중복이 있으면 중단합니다. 이미 공개된 원고는 제외합니다. 새 렌더링용 승인 fixture도 만들지 않습니다. 임시 복사본은 생성 후 삭제하며 실제 콘텐츠·번역 자료·일반 `dist`는 그대로 유지되어야 합니다.

파일의 고정 버전은 표시된 Git 커밋입니다. 커밋되지 않은 변경은 포함하지 않으며 원고 링크도 같은 커밋을 가리킵니다. 원고를 고쳤다면 커밋한 뒤 새 파일명으로 다시 생성해야 합니다. 기존 파일을 덮어쓰지 않습니다.

## 저장과 공개 범위

출력은 이 프로젝트의 모든 등록된 worktree 밖 새 `.html` 파일로 제한합니다. 심볼릭 링크로 작업 디렉터리를 가리키는 경로도 거부합니다. 새 파일 권한은 600이며 새 상위 폴더는 700으로 만듭니다. 이미 있는 폴더의 권한을 변경하지 않습니다.

검토 HTML과 원고 데이터는 공개 사이트·RSS·사이트 검색·사이트맵·CI 산출물에 추가하지 않습니다. CI는 `--output` 없이 생성 가능 여부와 수만 확인합니다. 이 도구의 검토 항목은 공개 글의 내부 항목 차단 정책과 별개인 로컬 자료입니다.

비교 화면은 추가 다운로드 없이 동작하며 CSP로 외부 연결·이미지·폰트 로딩을 차단합니다. 원고는 `textContent`로 표시하고, HTML에 넣는 JSON은 script 종료 문자열 등을 이스케이프합니다. 외부 링크는 HTTPS와 새 탭의 `noopener noreferrer`를 사용합니다. 파일을 직접 다른 사람이나 서버에 복사하면 내용도 함께 전달되므로 로컬 보관 범위를 사용자가 결정합니다.

저장된 검토와 근거를 재사용하는 자료이며 새 번역·외부 사실 재검증·사람이나 원어민의 의미 검토를 완료했다는 뜻이 아닙니다. 원래 뉴스 기준일과 기존 검토 시점을 확인하며 읽어야 합니다. 문서를 본 것만으로 현재 내용의 정확성이나 게시 승인을 자동 판정하지 않습니다.
