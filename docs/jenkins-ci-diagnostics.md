# Jenkins 예제 CI 진단

`python3 -B scripts/check_jenkins_examples.py`는 공개 한영 예제의 전체 Python 파일을 그대로 추출해 실행합니다. Linux 컨테이너용 Docker 엔진이 필요합니다. CI 이미지는 `.github/workflows/site-checks.yml`에서 digest로 고정합니다.

PR #80의 [첫 CI 실행](https://github.com/youdozi/youdozi.github.io/actions/runs/40647766798/attempts/1)은 첫 컨트롤러의 `/login` 준비 대기 180초를 초과했습니다. [동일 커밋 재실행](https://github.com/youdozi/youdozi.github.io/actions/runs/40647766798/attempts/2)은 재생성·복구를 포함해 통과했습니다. 이미지 고정 이후에도 발생했으므로 이미지 변경이 원인이라고 판단할 근거는 없습니다. 당시 컨테이너 상태를 남기지 않아 원인은 확정하지 않았습니다.

## 수집 범위

실행기는 각 예제의 시작 이름을 먼저 출력하고, 별도 스레드에서 실습 컨트롤러를 약 2초 간격으로 읽습니다. 예제 종료·실패·실행 제한 시간 초과 시 `jenkinsDiagnostics` JSON을 출력합니다. 진단 중 Docker 오류가 발생해도 예제의 성공·실패 판정을 바꾸지 않습니다.

- 관측 시작 시 이미 존재한 컨테이너는 제외합니다. 새 이름이 `jenkins-proof-12자리소문자16진수-controller-숫자`인 컨테이너만 최대 8개 관측합니다.
- Docker 실행 여부·OOM 여부·종료 코드·허용된 상태 값만 기록합니다. 환경 변수, inspect 전체 응답, 볼륨 내용과 암호는 출력하지 않습니다.
- 최근 로그 400줄에서 초기화 시작·완료, 전체 기동 완료, 초기 설정 필요, 메모리 부족, DNS 오류 문자열의 존재 여부만 기록합니다. 원시 로그는 출력하거나 파일·CI 산출물로 저장하지 않습니다.
- Docker가 공개한 `127.0.0.1`의 숫자 포트에만 `/login`을 요청합니다. 상태 코드와 `X-Jenkins` 헤더 존재 여부만 남깁니다. 리디렉션을 따라가지 않고 본문·쿠키·헤더 값을 읽어 출력하지 않습니다.
- 컨테이너마다 상태가 달라진 최근 8개 표본을 보존합니다. 컨테이너가 제거되어도 마지막 표본은 남습니다. Docker 읽기는 요청당 최대 2초, HTTP 읽기는 최대 1초입니다.

전용 CI runner에서는 해당 작업의 실습을 관측합니다. 로컬의 같은 Docker 엔진에서 동일한 이름 규칙의 다른 실습을 동시에 시작하면 그 컨트롤러도 관측될 수 있습니다. 진단 코드는 컨테이너·이미지·볼륨을 생성·변경·삭제하지 않습니다.

## 결과 해석

`Running: false`와 종료 코드는 표본 시점의 종료 상태입니다. `OOMKilled: true`는 Docker가 보고한 OOM 상태입니다. 로그의 `outOfMemoryReported`·`dnsFailureReported`는 해당 문자열이 표본에 있었다는 뜻이며 이것만으로 이번 실패의 원인을 확정하지 않습니다. false도 관련 문제가 없었다는 증거가 아닙니다.

`fullyRunning`이 관측되었는데 예제가 준비 대기에서 실패했다면 로컬 HTTP 상태·초기 설정 단계와 함께 살펴봅니다. 별도 HTTP 관측은 리디렉션을 따르지 않으므로 예제의 urllib 검사와 응답이 다를 수 있습니다. HTTP 302·503이나 표본 누락을 예제의 성공·실패 판정으로 사용하지 않습니다. 아직 기동 중이거나 표본 사이에 생성·삭제된 컨테이너는 진단에 없을 수 있습니다.

진단 추가로 원고 코드·로그인 성공 조건·180초 준비 대기·예제당 600초 실행 제한·재생성·복구 검사는 바뀌지 않습니다. 자동 재시도나 실패 무시도 추가하지 않습니다. 실패한 예제의 stderr 전체를 출력하는 대신 종료 코드와 확인된 준비 대기 초과 여부만 표시합니다.

## 검증

`python3 -m unittest discover -s scripts -p 'test_jenkins*.py' -v`로 공개 예제 계약과 진단의 비밀 값 제외, 읽기 작업 제한, 루프백 제한, 스레드 종료, 기록 상한, 실패 전달을 확인합니다. 이 모의 검사는 실제 Docker 기동을 입증하지 않으며 실제 실행 결과는 해당 커밋의 CI를 확인합니다.
