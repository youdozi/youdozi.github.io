# 기술 번역의 승인 후 게시 준비

기술 글 추가 언어는 기존 뉴스 번역과 별도 컬렉션인 `src/content/technical-translations/`에서 읽습니다. 현재 공개 파일은 없으며 배열 연산 12편과 셸 자동화 18편은 여전히 미게시입니다. [등록 목록](../.pipeline/technical-translations/batches.json)이 검사 대상 묶음을 지정합니다. 이 기능을 병합해도 원고는 자동 게시되지 않습니다.

## 게시 전 확인

```sh
npm run check:technical-publications
npm run review:technical-translations -- \
  --output ~/.config/youdozi-blog-review/technical-review-new.html
```

기술 번역의 원문·초안·그림을 비교한 뒤, 실제 사용자가 선택한 고정 목록 전체 원고의 게시를 승인했을 때만 아래 명령을 사용합니다. `<...>`를 실제 승인 정보로 바꾸며, 이 문서의 예시는 승인이 아닙니다. 현재 게시 준비는 선택한 묶음 전체를 대상으로 하므로 일부 원고에 대한 승인만 받았다면 실행하지 않습니다.

```sh
node scripts/technical-publication.mjs publish \
  --manifest .pipeline/technical-translations/batch-052/manifest.json \
  --manifest-sha256 '<검토 화면에 표시된 manifest SHA-256>' \
  --reviewed-by '<실제 승인자>' \
  --approval-pr '<실제 검토 PR 번호>' \
  --approval-basis '<선택한 묶음을 게시하라는 사용자 요청의 근거>'
```

기본 명령과 `check`는 읽기 전용입니다. `publish`는 현재 manifest 해시·원문·초안·그림·승인 정보를 모두 확인한 뒤 선택한 묶음의 새 Markdown을 준비하며, 기존 파일은 덮어쓰지 않습니다. 중간에 충돌하면 이번 실행이 만든 파일만 제거합니다. 기존 초안 목록의 승인 필드를 수정하거나 Git 커밋·PR·병합·배포·검색엔진 제출을 수행하지 않습니다. 이 준비 파일을 검토용 게시 PR로 제출하고 검사를 통과한 뒤 승인 범위에 따라 병합·배포합니다.

승인 자료는 각 게시 파일의 JSON 형식 frontmatter에 저장합니다. 상태는 approved이며 검토자·PR·근거·승인 시각을 기록합니다. 발행일은 해당 언어판을 준비한 실제 시각이고 원문 게시일을 복사하지 않습니다. 카테고리·태그·주소의 slug는 영어 기준문에서 가져오며 제목·설명·전체 본문은 고정된 번역 초안과 대조합니다. 그림 링크만 실제 공개 자산 경로로 바꿉니다. 코드와 참고 링크는 바꾸지 않습니다.

원문·초안·그림 또는 고정 목록이 변경되면 기존 승인 파일도 빌드에서 차단합니다. 새 원문을 반영한 번역과 승인 자료를 다시 준비해야 합니다. 등록 목록에 있는 묶음만 처리합니다. 기존 묶음의 승인 해시로 다른 묶음을 게시할 수 없습니다. `--manifest`를 생략한 기존 호출은 배열 연산 12편만 대상으로 하므로, 승인 시에는 묶음 경로도 명시하세요.

## 실제 출력

승인 파일은 공통 기사 경로 `/{언어}/posts/{slug}/`로 렌더링합니다. 같은 `translationKey`를 기준으로 실제 제공 언어만 상호 hreflang에 포함하고 영어를 x-default로 사용합니다. 언어별 검색·목록·RSS·사이트맵·JSON-LD·날짜·댓글 식별자·코드 도구를 기존 공통 처리로 연결합니다. 검색에는 전체 번역 본문이, RSS에는 해당 언어판의 제목·설명과 발행·수정 시각이 들어갑니다.

`prepare-public.mjs`는 승인 자료를 다시 검사한 뒤 해당 그림만 `public/assets/diagrams/technical/`에 준비합니다. 이 폴더는 생성 전용이며 승인 파일에서 제거된 원고의 오래된 그림도 제거합니다. 미게시 초안의 그림이나 내부 승인 자료는 공개 산출물로 복사하지 않습니다. 현재의 en/ko 학습 안내와 이전·다음 학습 경로는 유지합니다. 추가 6개 언어에도 8개 분야의 학습 안내 문구를 준비했으며, 실제 게시된 같은 언어의 기술 글이 있을 때만 안내·언어 링크·사이트맵·읽기 경로를 생성합니다. 본문에 있는 영어 참고 링크도 그대로 유지합니다.

## 격리된 통합 검사

```sh
npm run check:technical-preview
```

이 명령은 커밋된 HEAD의 임시 복사본에만 등록된 기술 번역 96편과 대기 뉴스 번역 318편을 시험용 승인 자료로 넣습니다. 일반 빌드·게시·배포·IndexNow 명령을 호출하지 않습니다. 이미 공개된 기술 번역이 있으면 덮어쓰지 않고 건너뜁니다.

시험용 승인에는 `render-fixture` 종류와 `AUTOMATED_RENDER_FIXTURE_NOT_HUMAN_APPROVAL` 검토자를 명시합니다. 실제 저장소 밖의 전용 임시 폴더, Git 체크아웃이 아닌 경로, 원본 저장소 경로와 정확한 원고 키를 기록한 격리 표식이 모두 있어야 읽을 수 있습니다. 일반 게시 승인으로 인정하지 않습니다.

정적 빌드와 내부 링크·SEO·메타데이터·목록·학습 경로·탐색·편집 기록 차단·그림 크기 검사를 실행합니다. 기술 번역의 모든 설명 문단·표 행·모든 언어 태그의 완전한 코드·그림·제목·설명을 실제 기사/검색/RSS와 대조하고, 한영 대응 글을 포함한 언어 연결도 검사합니다. 혼합 RSS는 각 기술 글과 뉴스의 실제 언어판 수정 시각으로 정렬해 최신 30개를 확인합니다. 알 수 없는 종류의 글에 날짜를 추정해서 부여하지 않습니다.

실행 후 임시 복사본을 지우고 실제 `src/content`, 뉴스/기술 번역 초안 및 일반 `dist`의 지문이 달라지지 않았는지 확인합니다. CI는 격리 검사 후에도 원래의 일반 빌드 산출물을 업로드합니다. 검사 통과는 게시 승인·번역 의미의 독립 검토·검색 색인이나 노출을 뜻하지 않습니다.

`npm test`의 통합 테스트는 임시 콘텐츠로 작업 폴더의 `dist`도 빌드합니다. 따라서 일반 테스트·빌드와 격리 미리보기/브라우저 검사를 동시에 실행하지 않습니다. 테스트 후 일반 빌드를 마치고, 그다음 격리 검사를 실행합니다. 격리 검사 중에는 원본 콘텐츠·번역 원고·`dist`를 변경하지 않아야 종료 시 지문 대조가 유효합니다.
