# 공개 글의 내부 편집 항목 차단

공개 글에는 뉴스·기술 설명·소식 기준일·실제 후속 사실·출처를 표시합니다. 편집 제안·검토 기록·후보 검토 카드는 별도 검토 화면과 저장소에서 관리합니다. 독자용 렌더링은 `readerMarkdown`, `ArchiveRenewal`, `DigestSection`이 담당합니다.

`npm run build`는 HTML 생성 후 `scripts/check_reader_content.py`를 실행합니다. 알려진 내부 항목이 남으면 종료 코드 1로 실패하며, CI는 사이트 산출물 업로드와 배포로 진행하지 못합니다. 자동 삭제나 원고 승인을 수행하는 기능은 아닙니다.

## 검사 대상

공개 언어는 영어·한국어와 실제 공개 번역 파일의 언어에서 결정합니다. `.pipeline/`의 미게시 번역은 읽지 않습니다. 언어별 검색 인덱스의 URL을 공개 글 목록으로 삼고 각 글의 생성 HTML·검색 제목·설명·본문과 RSS를 검사합니다. 기본 RSS와 언어별 RSS 모두 포함합니다. 현재는 글 423편, 검색 인덱스 8개, RSS 9개입니다. 공개 글이 늘면 목록에 따라 검사 수도 늘어납니다.

- `검토 기록`, `검토/보강`, `검토 시점 후속 확인`, `편집 제안`, `활용 가이드`, 내부 검토일·자동 분류 기록 등 기존 편집 형식.
- 8개 언어의 기존 아카이브 UI에 정의된 내부 배너·검토 제목·편집 안내 문구.
- `data-candidate-review`, `data-review-fields`, `candidate-review`로 식별되는 검토 카드. 숨긴 카드도 공개 글 본문에 있으면 실패합니다.
- 해당 원고의 알려진 `reviewFocus` 의견과 검색 인덱스의 내부 검토 필드. 오류 메시지에는 의견 원문 대신 파일 경로와 규칙 이름만 표시합니다.
- 누락·손상·빈 검색 인덱스와 RSS, 중복 글 URL, 생성 HTML 누락, 인덱스에 없는 RSS 글. 경로는 출력 디렉터리 내부로 제한합니다.

별도 `/review/` 화면과 미게시 원고는 공개 글 목록에 포함되지 않습니다. 이 화면은 인증으로 보호되는 비공개 페이지라는 뜻이 아닙니다. 기존 `noindex`와 사이트맵 제외 정책을 유지합니다.

## 보존하는 내용과 한계

`코드 검토`, `보안 검토`처럼 정상적인 기술 설명에 등장하는 단어를 일괄 금지하지 않습니다. 코드 블록·인라인 코드·인용문은 HTML에서 제외해 검사하고, 검색용 Markdown은 fenced 코드와 인용문을 제외합니다. 출처 링크·기술적 정정·실제 후속 조건은 유지합니다.

검사는 알려진 편집 형식과 각 원고의 저장된 의견을 대조합니다. 모든 언어의 임의 표현을 이해하는 의미 검토나 사실 검증을 대신하지 않습니다. 새 내부 문구·템플릿을 도입하면 차단 규칙과 테스트도 함께 갱신해야 합니다. 정적 출력 검사이며 실제 검색엔진 색인이나 외부 캐시의 갱신을 확인하는 기능은 아닙니다.

```sh
python3 -m unittest discover -s scripts -p test_reader_content.py -v
python3 -B scripts/check_reader_content.py
python3 -B scripts/check_reader_content.py --dist /path/to/generated-site
```

검사에 실패하면 표시된 경로와 규칙을 보고 원고 또는 렌더러를 수정합니다. 정상적인 기술 설명이 잘못 잡혔다면 구체적인 재현 예제로 규칙을 좁힙니다. 검토 화면의 자료를 통째로 공개하거나 검사 단계를 생략해 해결하지 않습니다.
