LRU कैश उस प्रविष्टि को हटाता है जिसे सबसे लंबे समय से इस्तेमाल नहीं किया गया है। Java में ऐक्सेस क्रम वाला `LinkedHashMap` इस्तेमाल की गई प्रविष्टि को सबसे हाल में इस्तेमाल हुए सिरे पर ले जाता है। इससे अनुरोधों के क्रम में हिट और उनकी लागत की गणना की जा सकती है।

[Programmers के कैश अभ्यास](https://school.programmers.co.kr/learn/courses/30/lessons/17680) में शहरों के अंग्रेज़ी नामों की तुलना करते समय बड़े और छोटे अक्षरों में फ़र्क नहीं किया जाता। कैश हिट की लागत 1 और मिस की 5 है। क्षमता 0 से 30 तक हो सकती है और अधिकतम 100,000 अनुरोध आते हैं। ये अभ्यास में तय की गई लागतें हैं, डेटाबेस के जवाब का मापा हुआ समय नहीं।

## अनुरोध आने पर कैश में क्या बदलता है

![क्षमता शून्य हो तो लागत तुरंत लौटती है। अन्यथा get और put ऐक्सेस क्रम बदलते हैं और क्षमता पार होने पर सबसे लंबे समय से इस्तेमाल न हुई कुंजी हटती है।](/assets/diagrams/technical/hi-2021-08-17-cache.svg)

क्षमता शून्य हो तो विधि तुरंत परिणाम लौटाती है। अन्यथा get और put से कुंजी हाल में इस्तेमाल हुई कुंजियों के सिरे पर पहुँचती है। क्षमता पार हो तो उस कुंजी को हटाते हैं जिसका आखिरी इस्तेमाल सबसे पहले हुआ था।

## हर ऐक्सेस पर क्रम बदलें

पूरी क्लास `Solution.java` में सहेजें। इसके लिए Java 11 या उसके बाद का संस्करण चाहिए। मूल उदाहरण के स्थानीय परीक्षण में Java 11 को लक्ष्य बनाकर JDK 17 से संकलित किया गया था। विधि मानती है कि इनपुट अभ्यास की शर्तें पूरी करता है।

```java
import java.util.LinkedHashMap;
import java.util.Locale;

public class Solution {
    public int solution(int cacheSize, String[] cities) {
        if (cacheSize == 0) return 5 * cities.length;
        var cache = new LinkedHashMap<String, Boolean>(16, 0.75f, true);
        int cost = 0;
        for (String city : cities) {
            String key = city.toLowerCase(Locale.ROOT);
            cost += cache.get(key) == null ? 5 : 1;
            cache.put(key, Boolean.TRUE);
            if (cache.size() > cacheSize) {
                String oldest = cache.keySet().iterator().next();
                cache.remove(oldest);
            }
        }
        return cost;
    }
}
```

कंस्ट्रक्टर का अंतिम आर्ग्युमेंट `true` महत्वपूर्ण है। डिफ़ॉल्ट क्रम प्रविष्टि जोड़े जाने से तय होता है। [ऐक्सेस क्रम वाला LinkedHashMap](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/LinkedHashMap.html) `get` और `put` जैसे ऑपरेशन पर भी क्रम बदलता है। इस कोड में कभी null मान नहीं रखा जाता, इसलिए `get(key) == null` से मिस पहचाना जा सकता है।

क्षमता पार हो तो इटरेशन क्रम की पहली कुंजी हटाएँ। इसी कुंजी को सबसे लंबे समय से इस्तेमाल नहीं किया गया है। LFU में हटाने का निर्णय इस्तेमाल की आवृत्ति से होता है। `Locale.ROOT` से अंग्रेज़ी अक्षरों को छोटे अक्षरों में बदलने का परिणाम मशीन के डिफ़ॉल्ट लोकेल पर निर्भर नहीं रहता।

## हिट से अगली बार हटने वाली कुंजी क्यों बदलती है

क्षमता 2 होने पर नीचे दिए गए अनुरोधों की कुल लागत 21 है। कैश की सूची में सबसे पहले वह कुंजी है जिसका आखिरी इस्तेमाल सबसे पहले हुआ था।

| अनुरोध | परिणाम | अनुरोध के बाद कैश | कुल लागत |
| --- | --- | --- | --- |
| Jeju | मिस | jeju | 5 |
| Pangyo | मिस | jeju, pangyo | 10 |
| Jeju | हिट | pangyo, jeju | 11 |
| Seoul | मिस | jeju, seoul | 16 |
| Pangyo | मिस | seoul, pangyo | 21 |

तीसरे अनुरोध पर Jeju की स्थिति न बदलें तो अगली बार दूसरी कुंजी हट जाएगी। क्षमता 0 होने पर कोई प्रविष्टि नहीं रख सकते, इसलिए विधि तुरंत `5 * cities.length` लौटाती है। `Jeju` और `JEJU` दोनों से एक ही कुंजी बननी चाहिए।

मान लें कि हैश ऑपरेशन में औसतन स्थिर समय लगता है। तब M अनुरोधों, नाम की लंबाई L और क्षमता C के लिए छोटे अक्षरों में बदलने समेत कुल समय O(M×L) और संग्रहण O(C×L) है। अभ्यास में L और C पर लगी सीमाएँ ध्यान में रखें। इस उदाहरण में समवर्ती ऐक्सेस के व्यवहार की जाँच या कैश के प्रदर्शन का मापन नहीं किया गया है।
