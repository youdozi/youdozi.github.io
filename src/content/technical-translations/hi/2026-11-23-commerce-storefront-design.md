**भुगतान के बाद खाली स्क्रीन दिखे तो खरीदार पहले जानना चाहता है कि पैसे कटे या नहीं।** उसे ऐसी स्क्रीन दें जहाँ वह मौजूदा ऑर्डर का नतीजा जाँच सके। उत्पाद पेज से ऑर्डर इतिहास तक हर स्क्रीन की पुष्ट जानकारी के साथ वह कार्रवाई दिखाएँ जो खरीदार वहाँ कर सकता है।

[कॉमर्स एडमिन स्क्रीन वाले लेख](/en/posts/2026-11-23-commerce-admin-screen/) में ऑपरेटर अपुष्ट भुगतान वाला ऑर्डर जाँचता है। यहाँ उसी स्थिति को खरीदार की ओर से देखेंगे। मान लें कि एक विक्रेता कोरियाई वॉन में भौतिक सामान बेचता है और उसे खरीदार तक भेजता है। खरीदार खाते में साइन इन करके ऑर्डर देते हैं। छूट और शिपिंग की नीतियाँ उदाहरण के लिए हैं।

## हर स्क्रीन पर खरीदार क्या तय करता है?

| स्क्रीन | पहले क्या दिखाएँ | खरीदार का अगला कदम |
| --- | --- | --- |
| उत्पाद सूची और खोज | नाम और फ़ोटो, तुलना योग्य कीमतें, लागू फ़िल्टर | नतीजे सीमित करें या उत्पाद पेज खोलें |
| उत्पाद विवरण | चुने गए विकल्प की कीमत, उपलब्धता और शिपिंग शर्तें | विकल्प और मात्रा चुनकर कार्ट में जोड़ें |
| कार्ट | हर आइटम का विकल्प, मात्रा, राशि, अनुमानित कुल और चेकआउट रोकने वाले आइटम | मात्रा और सामान बदलकर चेकआउट पर जाएँ |
| चेकआउट | डिलीवरी पता, शिपिंग शुल्क, छूट, अंतिम राशि और बदलाव करने की जगह | शर्तें जाँचें और भुगतान का अनुरोध करें |
| ऑर्डर विवरण | ऑर्डर नंबर, भुगतान, शिपमेंट और रिफ़ंड की स्थितियाँ और बदलाव का इतिहास | स्थिति के अनुसार नतीजा जाँचें या शिपमेंट ट्रैक करें |

अगर सूची में “₩39,000 से शुरू” लिखा है, तो उत्पाद पेज पर विकल्प चुनते ही उसकी वास्तविक कीमत दिखाएँ। बिक चुके विकल्प का नाम लिखकर उसकी स्थिति बताएँ। खोज में कुछ न मिले तो लागू फ़िल्टर दिखाएँ और उन्हें हटाने दें। खोज लोड न हो तो फिर कोशिश करने दें।

[स्टॉक आरक्षण वाले लेख](/en/posts/2026-11-22-commerce-system-design-last-unit-of-stock/) की नीति लागू करें। उत्पाद पेज पर जाँच के समय का स्टॉक दिखता है। कार्ट खरीदार की पसंद सहेजता है। सर्वर ऑर्डर बनाते समय स्टॉक आरक्षित करता है। आखिरी इकाई पहले किसी और को मिल जाए तो कार्ट में प्रभावित सामान और विकल्प चिह्नित करें। बाकी सामान और भरा हुआ पता बनाए रखें।

## भुगतान से पहले जाँच और बदलाव का अवसर दें

अंतिम राशि के साथ विकल्प, मात्रा और डिलीवरी पता दिखाएँ। खरीदार इन्हें जाँच और बदल सके। बटन पर वास्तविक कार्रवाई लिखें, जैसे **“₩43,000 का भुगतान करें।”** वित्तीय लेनदेन की त्रुटियों से बचने पर WCAG के मार्गदर्शन में सबमिट करने से पहले विवरण जाँचने और सुधारने की सुविधा बताई गई है। [वित्तीय लेनदेन में त्रुटि की रोकथाम पर W3C का मार्गदर्शन](https://www.w3.org/WAI/WCAG22/Understanding/error-prevention-legal-financial-data.html)

कार्ट में जोड़ते समय कीबोर्ड की कीमत ₩39,000 थी और चेकआउट पर ₩42,000 हो गई तो प्रभावित आइटम का नाम दें। उदाहरण के लिए, “काले कीबोर्ड की कीमत ₩39,000 से बदलकर ₩42,000 हो गई है।” छूट और शिपिंग फिर गिनकर नया कुल दिखाएँ और भुगतान अनुरोध से पहले खरीदार से उसकी पुष्टि कराएँ। ऑर्डर बनाते समय सर्वर खरीदार की पुष्ट राशि को वसूली जाने वाली राशि से मिलाता है और लेनदेन की शर्तें दर्ज करता है। [कॉमर्स डेटाबेस में ऑर्डर की राशि कैसे सहेजें](/en/posts/2026-11-22-commerce-database-design/)

मोबाइल पर पता और आइटम बदलने के लिंक संबंधित विवरण के पास रखें। भुगतान बटन के पास अंतिम राशि दिखाएँ। बटन नीचे स्थिर हो तो पर्याप्त स्क्रॉल मिलना चाहिए ताकि आखिरी फ़ील्ड और त्रुटि संदेश भी पढ़े जा सकें। कार्ट के कुल या भुगतान जाँच के नतीजे जैसे अपडेट में फ़ोकस वहीं रह सकता है। सहायक तकनीक को इसकी सूचना देने के लिए, मसलन, नतीजे का पाठ बदलने वाले हिस्से में `role="status"` जोड़ें। [स्थिति संदेशों पर W3C का मार्गदर्शन](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)

## सर्वर से भुगतान का नतीजा जाँचें

![भुगतान पेज से लौटने पर मौजूदा ऑर्डर जाँचें। लोड होने और जाँच विफल होने के अलग संदेश दें। फिर ऑर्डर और भुगतान के अनुसार स्थिति फिर जाँचने, शिपमेंट ट्रैक करने, उत्पाद देखने या रिफ़ंड की जानकारी पाने का विकल्प दें।](/assets/diagrams/technical/hi-2026-11-23-commerce-storefront-design.svg)

भुगतान पेज से लौटने पर सर्वर से मौजूदा ऑर्डर जाँचें। भुगतान बटन दबाने के बाद ऑर्डर बनने का जवाब खो जाए तो उसी अनुरोध कुंजी से देखें कि ऑर्डर पहले ही स्वीकार हुआ या नहीं। बटन को थोड़ी देर निष्क्रिय करने से बार-बार क्लिक घट सकते हैं। एक ही ऑर्डर दो बार बनने से रोकने के लिए सर्वर पर अनुरोध कुंजी की अनन्यता जाँचें। ऑर्डर विवरण और स्थिति के API यह भी जाँचें कि मौजूदा खरीदार को उस ऑर्डर तक पहुँच की अनुमति है।

| सर्वर से जाँची स्थिति | खरीदार के लिए संदेश और कार्रवाई |
| --- | --- |
| ऑर्डर की स्थिति जाँचना विफल | “ऑर्डर की स्थिति लोड नहीं हो सकी।” → **स्थिति फिर लोड करें** |
| ऑर्डर मौजूद है, भुगतान का नतीजा अज्ञात | “हम भुगतान का नतीजा जाँच रहे हैं।” → **ऑर्डर की स्थिति ताज़ा करें** |
| भुगतान पूरा, ऑर्डर की जाँच जारी | “आपका भुगतान हो गया है। हम ऑर्डर जाँच रहे हैं।” → **ऑर्डर की स्थिति ताज़ा करें** |
| भुगतान और ऑर्डर पुष्ट | “हमें आपका ऑर्डर मिल गया है।” → **शिपमेंट ट्रैक करें** |
| बिना शुल्क ऑर्डर रद्द होने की पुष्टि | “आपका ऑर्डर रद्द हो गया है। पैसे नहीं कटे हैं।” → **उत्पाद देखें** |
| रद्द होने के बाद भुगतान पुष्ट, रिफ़ंड लंबित | “आपके रिफ़ंड की प्रक्रिया चल रही है।” → **रिफ़ंड की स्थिति ताज़ा करें** |
| रिफ़ंड की पुष्टि | “आपका रिफ़ंड पूरा हो गया है।” → **रिफ़ंड विवरण देखें** |

शिपमेंट की वास्तविक स्थिति देखकर बताएँ कि ऑर्डर तैयार हो रहा है, रास्ते में है या पहुँच चुका है। रद्द करने या वापस करने का बटन तभी दिखाएँ जब मौजूदा स्थिति में अनुरोध मान्य हो और उपयोगकर्ता को अनुमति हो। अनुरोध स्वीकार होने के बाद उसकी प्रगति दिखाएँ। रिफ़ंड पूरा होने का संदेश सर्वर की पुष्टि पर दिखाएँ।

## सर्वर की स्थितियों से संदेश और कार्रवाई चुनें

उदाहरण सर्वर से पढ़ी गई ऑर्डर और भुगतान की स्थितियों से शीर्षक और अगली कार्रवाई चुनता है। नेटवर्क त्रुटि और भुगतान का अज्ञात नतीजा अलग इनपुट हैं। अपरिभाषित संयोजन पर सफलता नहीं दिखाई जाती। कोड में इंटरफ़ेस के मूल कोरियाई संदेश हैं। ऊपर की तालिका में उनके हिंदी अर्थ हैं। कोड को `order-view.mjs` नाम से सहेजें और `node order-view.mjs` चलाएँ।

```javascript
const labels = {
  loading: ["주문 상태를 불러오는 중입니다.", null],
  unavailable: ["주문 상태를 불러오지 못했습니다.", "주문 상태 다시 불러오기"],
  pending: ["결제 결과를 확인 중입니다.", "주문 상태 새로고침"],
  paidReview: ["결제는 완료됐고 주문을 확인 중입니다.", "주문 상태 새로고침"],
  confirmed: ["주문이 접수됐습니다.", "배송 상태 보기"],
  closed: ["주문이 취소됐으며 결제된 금액이 없습니다.", "상품 다시 보기"],
  refundPending: ["환불을 처리 중입니다.", "환불 상태 새로고침"],
  refunded: ["환불이 완료됐습니다.", "환불 내역 보기"]
};

function orderView(snapshot) {
  if (snapshot.kind === "loading") return labels.loading;
  if (snapshot.kind === "unavailable") return labels.unavailable;

  const { order, payment } = snapshot;
  if (order === "CANCELLED" && payment === "REFUND_PENDING") {
    return labels.refundPending;
  }
  if (order === "CANCELLED" && payment === "REFUNDED") {
    return labels.refunded;
  }
  if (order === "CANCELLED" && payment === "CLOSED_UNPAID") {
    return labels.closed;
  }
  if (order === "CONFIRMED" && payment === "PAID") {
    return labels.confirmed;
  }
  if (order === "PENDING_PAYMENT" && payment === "PAID") {
    return labels.paidReview;
  }
  if (order === "PENDING_PAYMENT" &&
      (payment === "PENDING" || payment === "UNKNOWN")) {
    return labels.pending;
  }
  return labels.unavailable;
}

const verified = (order, payment) => ({ kind: "loaded", order, payment });
const cases = [
  [{ kind: "loading" }, "loading"],
  [{ kind: "unavailable" }, "unavailable"],
  [verified("PENDING_PAYMENT", "UNKNOWN"), "pending"],
  [verified("PENDING_PAYMENT", "PAID"), "paidReview"],
  [verified("CONFIRMED", "PAID"), "confirmed"],
  [verified("CANCELLED", "CLOSED_UNPAID"), "closed"],
  [verified("CANCELLED", "REFUND_PENDING"), "refundPending"],
  [verified("CANCELLED", "REFUNDED"), "refunded"],
  [verified("CONFIRMED", "UNKNOWN"), "unavailable"]
];

for (const [input, key] of cases) {
  if (orderView(input) !== labels[key]) throw new Error(key);
  console.log("PASS", key);
}
```

Node.js 22.17.0 पर सभी नौ इनपुट पास हुए। जाँच विफल होने, भुगतान अपुष्ट रहने, बिना शुल्क ऑर्डर रद्द होने और रिफ़ंड लंबित रहने पर अपेक्षित संदेश और कार्रवाई मिले। इस रन में सर्वर की स्थिति को स्क्रीन के संदेश और कार्रवाई से जोड़ने वाला फ़ंक्शन जाँचा गया। मोबाइल पर उपयोग, सहायक तकनीक का व्यवहार और वास्तविक भुगतान एकीकरण की जाँच तैयार स्क्रीन पर करनी होगी।
