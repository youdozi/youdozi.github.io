Подготовка черновика новостей остановилась с ошибкой `ENOENT`. Из 4 разобранных сбоев 3 произошли, когда Astro пытался прочитать размеры изображений в уже опубликованных статьях. В чистой копии репозитория нужные SVG ещё не были созданы. Если файлы оставались от предыдущей локальной сборки, та же проверка могла пройти. [Сбой проверки черновика](https://github.com/youdozi/youdozi.github.io/actions/runs/45548722494)

## Одна проверка до и после генерации SVG

Мы извлекли проблемный коммит в отдельный каталог. Команда `npm run check` завершилась с кодом 1. В том же каталоге мы запустили `node scripts/prepare-public.mjs` для подготовки статических ресурсов, и повторная проверка завершилась с кодом 0. Сборка тоже готовит ресурсы, но в CI проверка запускалась раньше.

![В чистой копии репозитория создаются SVG, затем Astro читает размеры изображений, после чего запускается сборка сайта.](/assets/diagrams/technical/ru-2026-11-26-astro-clean-checkout.svg)

Чтобы повторить последовательность CI, используйте Node.js 24 и Python 3.11 в корневом каталоге репозитория. Установите зависимости командой `npm ci`, затем выполните команды ниже. Следующий шаг запускается только после успешного завершения предыдущего. [Исправление в PR](https://github.com/youdozi/youdozi.github.io/pull/198) · [Результат сборки PR](https://github.com/youdozi/youdozi.github.io/actions/runs/45734945701)

```sh
node scripts/prepare-public.mjs &&
  npm run check &&
  npm run build
```

## Отдельный сбой на этапе генерации

В другом запуске Gemini вернул HTTP 503 при генерации. После исправления повторные запросы идут к той же модели с задержкой в 1 секунду перед первым повтором и 2 секунды перед вторым. Эти две попытки распределяются между всеми запросами за весь запуск. [Сбой на этапе генерации](https://github.com/youdozi/youdozi.github.io/actions/runs/45098322259)

Для пробного запуска на корейском и английском мы взяли официальную статью Spring. Имитировали только ответы модели при генерации и рецензировании. Цитаты сверили с оригиналом, проверили ссылки и соответствие материала схемам Python и Astro. Пробный запуск ничего не записал ни в черновики, ни в очередь. Доступность сервиса Gemini при этом не проверялась.

Если проверка проходит локально, найдите команду, которая первой читает отсутствующий файл в чистой копии репозитория. Сопоставьте её со стадией создания файла. Их порядок может объяснить, почему полная сборка проходит, хотя предшествующая ей проверка падает.
