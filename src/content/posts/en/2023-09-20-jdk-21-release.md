Virtual threads, sequenced collections, record patterns and pattern matching for switch are final features in JDK 21 and work without preview flags. String templates were still a preview feature in that release; upgrading the JDK does not give every new feature the same stability status. The [JDK 21 release notes](https://www.oracle.com/java/technologies/javase/21all-relnotes.html) distinguish final, preview and incubator features.

[Java 21 became generally available](https://inside.java/2023/09/19/the-arrival-of-java-21/) on September 19, 2023. This article revisits that release through a reproducible example. It does not recommend the latest JDK or a production patch version.

## Feature status in JDK 21

| Feature | Status in JDK 21 | What to check |
| --- | --- | --- |
| Virtual threads | Final | Consider them for many I/O-bound tasks; they do not guarantee faster CPU computation |
| Sequenced collections | Final | Consistent APIs for first/last elements and reverse-ordered views |
| Record patterns and pattern matching for switch | Final | Deconstruct values and branch on patterns |
| String templates | Preview | Do not assume later JDK releases retain them |
| Structured concurrency | Preview | Assess separately from the finalization of virtual threads |
| Vector API | Sixth Incubator | Distinguish incubating APIs from final and preview features |

This is a selected list. The [JDK 21 release notes](https://www.oracle.com/java/technologies/javase/21all-relnotes.html) also document preview and incubator status. Check the [Java 21 language changes](https://docs.oracle.com/en/java/javase/21/language/java-language-changes.html) for language feature status. String templates were not included in JDK 23; see their [history and standard alternatives](/en/posts/2023-09-23-jdk-21-string-templates/).

## Compile without preview flags

The following code ran locally on Zulu JDK 21.0.1. That old patch version records the reproduction environment; it is not a production recommendation. First check that `javac` and `java` resolve to the same JDK 21 installation.

### `Jdk21Example.java`

```java
import java.util.ArrayList;
import java.util.List;

public class Jdk21Example {
    record Point(int x, int y) {}

    static String describe(Object value) {
        return switch (value) {
            case null -> "missing";
            case Point(int x, int y) -> "point=" + x + "," + y;
            default -> "other";
        };
    }

    public static void main(String[] args) throws InterruptedException {
        var names = new ArrayList<>(List.of("alpha", "beta", "gamma"));
        var reverse = names.reversed();
        names.set(0, "ALPHA");
        System.out.println(names.getFirst() + "/" + names.getLast());
        System.out.println(reverse);
        System.out.println(describe(new Point(2, 3)));
        System.out.println(describe(null));
        Thread worker = Thread.ofVirtual().start(() ->
                System.out.println("virtual=" + Thread.currentThread().isVirtual()));
        worker.join();
    }
}
```

```sh
javac --release 21 Jdk21Example.java
java Jdk21Example
```

```text
ALPHA/gamma
[gamma, beta, ALPHA]
point=2,3
missing
virtual=true
```

`reversed()` returns a reverse-ordered view rather than an independent copy. After the first element in the original list changes, the last element in the reversed output is also `ALPHA`. Calling `getFirst()` on an empty collection would throw an exception; this example uses a nonempty list. The [SequencedCollection API](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/SequencedCollection.html) defines the view contract.

`Point(int x, int y)` is a record pattern, and `case null` handles null input separately. The virtual thread prints the final line, and `join()` waits for its completion. This checks API behavior without measuring throughput or latency. The [virtual thread guide](https://docs.oracle.com/en/java/javase/21/core/virtual-threads.html) explains their suitability for concurrency dominated by I/O waits.

Before changing an application runtime, check JDK 21 compatibility for its framework, build tooling, and instrumentation agents. JDK feature status and a distributor's support period are separate questions. [Temurin 21 release history and binary selection](/en/posts/2023-10-10-temurin-jdk21-delay/) covers how to check what a distributor actually published.
