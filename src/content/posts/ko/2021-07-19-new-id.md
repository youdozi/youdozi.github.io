신규 아이디 추천에서는 문자열 변환의 순서가 중요합니다. 특히 길이를 15자로 자른 뒤 끝에 남은 마침표를 한 번 더 제거해야 합니다. 앞에서 끝 마침표를 지웠다는 이유로 이 단계를 생략하면 잘못된 결과가 나올 수 있습니다.

[문제의 변환 규칙](https://school.programmers.co.kr/learn/courses/30/lessons/72410)은 ASCII 영문을 소문자로 바꾸고 허용 문자만 남긴 뒤, 마침표·빈 값·길이를 순서대로 정리하는 것입니다. 아래 두 풀이는 문제에서 보장하는 null이 아닌 입력을 전제로 합니다. Optional 풀이는 Java 11의 `repeat()`를 사용합니다. 두 코드 모두 Java 11 타깃으로 컴파일했고, 두 클래스를 같은 파일에 함께 넣지 말고 풀이 하나를 `Solution.java`로 저장하세요.

## 처리 흐름

그림은 Optional 버전의 순서입니다. 반복문 버전은 허용 문자 필터와 연속 점 제거를 한 번에 처리하며 같은 규칙을 유지합니다.

## Optional로 단계를 연결하기

```java
import java.util.Locale;
import java.util.Optional;

public class Solution {
    public String solution(String new_id) {
        return Optional.of(new_id)
                .map(s -> s.toLowerCase(Locale.ROOT))
                .map(s -> s.replaceAll("[^a-z0-9._-]", ""))
                .map(s -> s.replaceAll("[.]+", "."))
                .map(s -> s.replaceAll("^[.]|[.]$", ""))
                .map(s -> s.isEmpty() ? "a" : s)
                .map(s -> s.length() > 15 ? s.substring(0, 15) : s)
                .map(s -> s.replaceAll("[.]$", ""))
                .map(s -> s.length() < 3
                        ? s + s.substring(s.length() - 1).repeat(3 - s.length()) : s)
                .orElseThrow();
    }
}
```

`Locale.ROOT`는 기본 로캘에 따른 소문자 변환 차이를 피합니다. 허용 문자 패턴은 소문자 ASCII 영문·숫자·점·밑줄·하이픈만 남깁니다. 점이 연속되면 하나로 줄이고 양 끝의 점을 제거합니다. 필터 후 빈 값이면 `a`를 채운 다음 15자로 절단하고, 끝 점을 다시 정리한 뒤 마지막 문자를 반복해 최소 길이 3을 만듭니다.

Optional은 필수 자료구조가 아니라 변환 단계를 이어 쓰기 위한 선택입니다. `Optional.of`는 null을 허용하지 않으므로 null 입력을 빈 아이디로 조용히 바꾸지 않습니다.

## 같은 규칙을 반복문으로 구현하기

아래 풀이는 허용 문자 선별과 연속 점 제거를 한 순회에서 처리합니다. ASCII 대문자만 대응 소문자로 바꾸는 것은 문제의 입력 범위를 사용한 구현입니다. 일반적인 Unicode 이름 정규화에 그대로 확장하는 코드는 아닙니다.

```java
import java.util.Objects;

public class Solution {
    public String solution(String new_id) {
        Objects.requireNonNull(new_id);
        StringBuilder result = new StringBuilder();
        for (char input : new_id.toCharArray()) {
            char c = input >= 'A' && input <= 'Z' ? (char) (input + 32) : input;
            boolean allowed = (c >= 'a' && c <= 'z') || (c >= '0' && c <= '9')
                    || c == '-' || c == '_' || c == '.';
            if (!allowed || (c == '.' && (result.length() == 0
                    || result.charAt(result.length() - 1) == '.'))) continue;
            result.append(c);
        }
        if (result.length() > 0 && result.charAt(result.length() - 1) == '.') {
            result.setLength(result.length() - 1);
        }
        if (result.length() == 0) result.append('a');
        if (result.length() > 15) result.setLength(15);
        if (result.charAt(result.length() - 1) == '.') result.setLength(result.length() - 1);
        while (result.length() < 3) result.append(result.charAt(result.length() - 1));
        return result.toString();
    }
}
```

| 확인할 입력 | 결과 | 확인하는 규칙 |
| --- | --- | --- |
| `=.=` | `aaa` | 빈 값 대체와 길이 보충 |
| `z-+.^.` | `z--` | 허용 문자와 끝 점 제거 |
| `I` | `iii` | 영문 소문자와 기본 로캘 독립성 |
| `abcdefghijklmn.op` | `abcdefghijklmn` | 15자 절단 후 끝 점 제거 |

두 풀이 모두 입력 길이 n에 대해 선형 처리 범위의 변환이며 추가 공간은 O(n)입니다. 정규식 버전은 여러 중간 문자열을 만들고 반복문 버전은 StringBuilder를 사용합니다. 성능 측정 없이 한쪽이 언제나 빠르다고 결론 내리지는 않습니다. [String API](https://docs.oracle.com/en/java/javase/11/docs/api/java.base/java/lang/String.html)의 치환·소문자·반복 동작을 기준으로 확인할 수 있습니다.

같은 숫자 영단어를 리터럴로 바꾸는 경우는 [replace와 replaceAll 구분](/ko/posts/2021-07-23-number-word/)에서, 로캘과 키 정규화는 [LRU 캐시](/ko/posts/2021-08-17-cache/)에서 이어서 볼 수 있습니다.
