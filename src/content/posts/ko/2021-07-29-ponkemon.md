N개 중 N/2개를 골라 종류 수를 최대화한다면, 답은 `min(서로 다른 종류 수, N/2)`입니다. 고를 수 있는 개수보다 종류가 많아질 수 없고, 입력에 없는 종류를 만들 수도 없기 때문입니다.

[폰켓몬 문제](https://school.programmers.co.kr/learn/courses/30/lessons/1845)는 양의 짝수 N≤10,000과 1~200,000의 종류 번호를 입력으로 줍니다. 반환할 값은 선택 조합이 아니라 가능한 최대 종류 수 하나입니다.

## 처리 흐름

종류 수와 N/2 선택 제한은 모두 상한입니다. 문제 조건에서는 두 값의 최솟값을 달성할 수 있습니다.

## HashSet으로 종류 세기

다음 전체 코드를 `Solution.java`에 저장합니다. Java 11 타깃으로 컴파일하고 JDK 17에서 실행했습니다.

```java
import java.util.HashSet;
import java.util.Set;

public class Solution {
    public int solution(int[] nums) {
        Set<Integer> kinds = new HashSet<>();
        for (int kind : nums) kinds.add(kind);
        return Math.min(kinds.size(), nums.length / 2);
    }
}
```

[`HashSet`](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/HashSet.html)은 같은 번호를 한 번만 저장합니다. 따라서 `kinds.size()`가 종류 수 u이고, 선택 개수 k는 `nums.length / 2`입니다. 반복 횟수나 개체별 출현 빈도를 보관할 필요가 없습니다.

## 상한이 실제로 가능한 이유

u≥k이면 서로 다른 k종류에서 하나씩 선택하면 k종류를 얻습니다. u<k이면 모든 u종류를 하나씩 고른 뒤, 남은 개수 k-u를 다른 개체로 채울 수 있습니다. 전체 N개 중 u개만 사용했고 k≤N이므로 채울 개체 수는 충분합니다. 따라서 상한 `min(u, k)`를 실제로 달성할 수 있습니다.

| 입력 | 종류 수 u | 선택 개수 k | 답 |
| --- | --- | --- | --- |
| `[3,1,2,3]` | 3 | 2 | 2 |
| `[3,3,3,2,2,2]` | 2 | 3 | 2 |
| `[7,7]` | 1 | 1 | 1 |

해시가 적절히 분산되는 평균 조건에서 시간 O(N), 추가 공간 O(u)입니다. 선택한 개체의 인덱스까지 반환해야 한다면 이 코드만으로는 부족하며, 실제 구성 절차가 추가로 필요합니다. 여기서는 문제에서 요구하는 개수만 계산합니다.

작은 입력은 N/2개를 고르는 모든 인덱스 조합을 열거한 기준 결과와 비교했고, 최대 길이 10,000에서 모두 다른 종류와 모두 같은 종류도 확인했습니다. 이는 반환값 검증이며 해시 구현의 속도 벤치마크는 아닙니다.

동명이인의 인원수처럼 중복의 **개수**가 필요한 상황은 [미완주 선수의 빈도 맵](/ko/posts/2021-07-23-unsuccessful-runner/)과 비교하세요.
