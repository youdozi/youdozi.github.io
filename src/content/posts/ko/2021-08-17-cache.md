LRU 캐시는 가장 최근에 접근하지 않은 항목부터 내보냅니다. Java에서는 `LinkedHashMap`을 접근 순서 모드로 만들면 조회한 항목이 최근 위치로 이동하므로, 도시 이름을 처리하는 순서대로 적중 여부와 비용을 계산할 수 있습니다.

[프로그래머스 캐시 문제](https://school.programmers.co.kr/learn/courses/30/lessons/17680)는 영문 도시 이름을 대소문자 구분 없이 비교하고, hit에 1·miss에 5의 비용을 부여합니다. 용량은 0~30, 요청은 최대 100,000개입니다. 이 비용은 문제의 계산 규칙이며 실제 DB 응답 시간을 측정한 값이 아닙니다.

용량 0은 즉시 반환합니다. 그 외에는 get·put으로 접근 순서를 갱신하고 용량을 넘으면 가장 오래 접근하지 않은 키를 제거합니다.

## 접근할 때 순서를 갱신하는 구현

아래 전체 코드를 `Solution.java`에 저장할 수 있습니다. Java 11 이상을 기준으로 작성했고, 로컬에서는 JDK 17로 Java 11 타깃 컴파일과 실행을 확인했습니다. 메서드는 문제 조건을 만족하는 입력을 전제로 합니다.

```java
import java.util.LinkedHashMap;
import java.util.Locale;

public class Solution {
    public int solution(int cacheSize, String[] cities) {
        if (cacheSize == 0) return 5 * cities.length;
        var cache = new LinkedHashMap<String, Boolean>(16, 0.75f, true);
        int cost = 0;
        for (String city : cities) {
            String key = city.toLowerCase(Locale.ROOT);
            cost += cache.get(key) == null ? 5 : 1;
            cache.put(key, Boolean.TRUE);
            if (cache.size() > cacheSize) {
                String oldest = cache.keySet().iterator().next();
                cache.remove(oldest);
            }
        }
        return cost;
    }
}
```

생성자의 마지막 인자 `true`가 핵심입니다. 기본 삽입 순서와 달리 [접근 순서 LinkedHashMap](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/LinkedHashMap.html)은 `get`과 `put` 등의 접근을 순서에 반영합니다. 이 코드에서는 값으로 null을 저장하지 않으므로 `get(key) == null`을 miss 판정에 사용할 수 있습니다.

용량을 초과하면 반복자의 첫 키, 즉 가장 오래 접근하지 않은 항목을 제거합니다. 접근 횟수가 가장 적은 항목을 고르는 LFU와는 다른 규칙입니다. `Locale.ROOT`는 실행 환경의 기본 로캘에 따라 영문 대소문자 변환 결과가 달라지는 것을 피합니다.

## hit도 순서를 바꾸는 이유

용량이 2이고 아래 순서로 요청하면 총비용은 21입니다. 표의 캐시는 오래된 항목부터 표시합니다.

| 요청 | 결과 | 요청 후 캐시 | 누적 비용 |
| --- | --- | --- | --- |
| Jeju | miss | jeju | 5 |
| Pangyo | miss | jeju, pangyo | 10 |
| Jeju | hit | pangyo, jeju | 11 |
| Seoul | miss | jeju, seoul | 16 |
| Pangyo | miss | seoul, pangyo | 21 |

세 번째 요청에서 Jeju를 최근 항목으로 옮기지 않으면 다음 퇴출 대상이 달라집니다. 용량 0은 아무 항목도 유지하지 못하므로 바로 `5 * cities.length`를 반환합니다. `Jeju`와 `JEJU`도 같은 키가 되어야 합니다.

해시 연산의 평균 비용을 상수로 보고 요청 수를 M, 이름 길이를 L, 용량을 C라 하면 정규화를 포함한 시간은 O(M×L), 저장 공간은 O(C×L)입니다. L과 C에 문제의 상한이 있다는 점도 고려하세요. 동시 접근이나 실제 캐시 성능 비교를 검증한 구현은 아닙니다.

숫자 계산의 범위는 [Java 내적과 int 범위](/ko/posts/2021-07-22-dot-product/)에서, 문자열 처리 순서는 [아이디 정규화](/ko/posts/2021-07-19-new-id/)에서 이어서 다룹니다.
