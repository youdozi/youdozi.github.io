**T3 Code आपके कंप्यूटर पर स्थापित कोडिंग एजेंटों के लिए एक इंटरफ़ेस देता है जहाँ आप प्रोजेक्ट, बातचीत, अनुमतियाँ और बदली हुई फ़ाइलें देख सकते हैं।** एजेंट को कोड सौंपते समय लंबे अनुरोध से ज़्यादा मायने रखता है कि काम छोटा हो और उसकी सफलता जाँची जा सके। यहाँ हम संख्यात्मक `Retry-After` पार्सर को ठीक करने के अनुरोध से लेकर diff और परीक्षण के परिणाम जाँचने तक के चरण देखेंगे।

यह लेख [आधिकारिक T3 Code प्रोजेक्ट](https://github.com/pingdotgg/t3code/tree/v0.1.9) के बारे में है। वेब ऐप बनाने के लिए `create-t3-app` इस्तेमाल करने वाला T3 Stack एक अलग प्रोजेक्ट है। आधिकारिक README के अनुसार इससे Codex, Claude Code और Cursor जैसे मौजूदा प्रदाता जोड़े जा सकते हैं। T3 Code स्थापित करने के अलावा प्रदाता के लिए लॉगिन और सदस्यता या API इस्तेमाल की शर्तें अलग से पूरी करनी होती हैं।

आधार [v0.1.9 रिलीज़](https://github.com/pingdotgg/t3code/releases/tag/v0.1.9) है, जिसकी जाँच 2026-11-12 को हुई। उदाहरण macOS पर Node.js 24.13.0 और Git के साथ जाँचा गया। T3 Code CLI की सहायता और स्थानीय सर्वर का शुरू होना भी जाँचा गया। **किसी प्रदाता को AI कार्य नहीं भेजा गया।** नीचे दिया संदर्भ समाधान सीधे परीक्षण किया हुआ कार्यान्वयन है। इससे T3 Code के वास्तविक आउटपुट या मॉडल के प्रदर्शन का दावा नहीं किया गया है।

## T3 Code और प्रदाता की क्या भूमिकाएँ हैं?

T3 Code प्रोजेक्ट और थ्रेड दिखाता है। इसमें प्रदाता चुन सकते हैं और अनुमति के अनुरोध व बदलाव देख सकते हैं। जुड़ा हुआ एजेंट फ़ाइलें पढ़ता और बदलता है या कमांड चलाता है। टूल कॉल दिखने भर से परीक्षण का चलना और पास होना साबित नहीं होता। वास्तविक कमांड और उसका परिणाम देखें।

[स्थापना गाइड](https://github.com/pingdotgg/t3code/blob/v0.1.9/docs/user/install.md) के अनुसार प्रदाता स्थापित करें और **उस कंप्यूटर पर प्रमाणीकरण पूरा करें जहाँ T3 Code सर्वर चलेगा**। अभ्यास पहले से तैयार प्रदाता चुनने से शुरू होता है। प्रॉम्प्ट में लॉगिन विवरण या API कुंजी डालने की ज़रूरत नहीं है।

## छोटा Git प्रोजेक्ट बनाएँ और विफल परीक्षण देखें

![प्रारंभिक कोड और तय परीक्षण Git में सहेजें और विफलता देखें। T3 Code में प्रोजेक्ट, प्रदाता और Supervised अनुमतियाँ चुनकर सीमित बदलाव का अनुरोध भेजें। एजेंट की फ़ाइलों और कमांड का दायरा देखकर अनुमति दें। diff, मूल परीक्षण और परिणाम मिलाएँ। शर्तें पूरी हों तो खुद कमिट करें, वरना सुधार माँगें।](2026-11-12-t3-code-workflow.svg)

ये तीन फ़ाइलें नए `t3-code-example` फ़ोल्डर में रखें। Node परीक्षणों में बाहरी पैकेज या API कॉल की ज़रूरत नहीं है। `Retry-After` के दो रूपों में से अभ्यास **केवल पूर्ण सेकंड वाले `delay-seconds`** को स्वीकार करता है। HTTP-date दायरे से बाहर है और उसके लिए `null` लौटाना है। हेडर का पूरा व्याकरण [RFC 9110 में Retry-After की परिभाषा](https://www.rfc-editor.org/rfc/rfc9110.html#name-retry-after) में देखें।

### `package.json`

```json
{
  "name": "t3-code-retry-after-example",
  "private": true,
  "type": "module",
  "engines": { "node": ">=24" },
  "scripts": { "test": "node --test retry-after.test.mjs" }
}
```

### `retry-after.mjs`

```javascript
export function retryAfterMs(header) {
  const seconds = Number.parseInt(header, 10);
  return Number.isFinite(seconds) ? seconds * 1000 : null;
}
```

### `retry-after.test.mjs`

```javascript
import test from 'node:test';
import assert from 'node:assert/strict';
import { retryAfterMs } from './retry-after.mjs';

const cases = [
  ['2', 2000],
  ['0', 0],
  [' 2 ', 2000],
  ['0002', 2000],
  ['', null],
  ['   ', null],
  [undefined, null],
  [null, null],
  [2, null],
  ['0x10', null],
  ['2x', null],
  ['-1', null],
  ['1.5', null],
  ['1e3', null],
  ['Infinity', null],
  ['Wed, 21 Oct 2015 07:28:00 GMT', null],
  ['9007199254740', 9007199254740000],
  ['9007199254741', null],
  ['9007199254740991', null],
];
for (const [input, expected] of cases) {
  test(`retryAfterMs(${JSON.stringify(input)})`, () => {
    assert.equal(retryAfterMs(input), expected);
  });
}
```

Git में कमिट लेखक की पहचान सेट करने के बाद प्रोजेक्ट फ़ोल्डर में ये कमांड चलाएँ।

```sh
git init -b main
git add package.json retry-after.mjs retry-after.test.mjs
git commit -m "Add Retry-After exercise"
npm test
```

प्रारंभिक कोड पर **11 परीक्षण पास और 8 विफल** हुए, कुल 19 परीक्षण थे। कोड `parseInt('2x', 10)` जैसे अंक से शुरू होने वाले कुछ स्ट्रिंग भी स्वीकार कर लेता है। यह ऋणात्मक संख्या, दशमलव या सुरक्षित सीमा से बड़े मान सही ढंग से नहीं सँभालता। अभ्यास इन्हीं विफल परीक्षणों से शुरू होता है।

## प्रोजेक्ट खोलें और बदलाव का दायरा बताएँ

तय संस्करण चलाने के लिए प्रोजेक्ट फ़ोल्डर से यह कमांड दें। `--host` पहुँच को स्थानीय कनेक्शन तक सीमित करता है और `--auto-bootstrap-project-from-cwd` मौजूदा फ़ोल्डर को प्रोजेक्ट में जोड़ता है। पहली बार npm पैकेज और निष्पादन योग्य फ़ाइल डाउनलोड हो सकते हैं।

```sh
npm exec --yes --package=t3@0.1.9 -- t3 \
  --host 127.0.0.1 --auto-bootstrap-project-from-cwd .
```

CLI स्थानीय सर्वर और वेब ऐप शुरू करता है। यदि T3 Code सर्वर पहले से चल रहा है तो उसी में प्रोजेक्ट खोलें। डेस्कटॉप स्थापना और दूरस्थ पहुँच के लिए [इस संस्करण की स्थापना गाइड](https://github.com/pingdotgg/t3code/blob/v0.1.9/docs/user/install.md) में अलग निर्देश हैं। इस अभ्यास में बैकग्राउंड सेवा या बाहरी नेटवर्क से पहुँच सेट नहीं की जाती।

प्रोजेक्ट फ़ोल्डर और थ्रेड चुनें, फिर स्थापित और प्रमाणित प्रदाता चुनें। [थ्रेड गाइड](https://github.com/pingdotgg/t3code/blob/v0.1.9/docs/user/thread-sidebar.md) के अनुसार **New worktree** अलग शाखा और कार्य निर्देशिका बनाता है। मूल अभ्यास तैयार फ़ोल्डर की मौजूदा कार्य निर्देशिका में होता है। नया worktree चुनने पर आगे के Git और npm कमांड भी उसी फ़ोल्डर में चलाएँ। पहले थ्रेड का पथ और शाखा देखें। संदेश लिखने की जगह पर अनुमति **Supervised** चुनें। [v0.1.9 की अनुमति गाइड](https://github.com/pingdotgg/t3code/blob/v0.1.9/docs/user/permission-modes.md) के अनुसार शुरुआती डिफ़ॉल्ट Full access है। Supervised में कमांड चलाने और फ़ाइल बदलने के लिए मंज़ूरी माँगी जाती है। कौन-सी फ़ाइलें बिना मंज़ूरी पढ़ी जा सकती हैं, जैसे विवरण प्रदाता पर निर्भर करते हैं।

यह प्रॉम्प्ट भेजें।

```text
पहले retry-after.mjs और retry-after.test.mjs पढ़ें।
retryAfterMs(header) को इन शर्तों के अनुसार सुधारें।

- दोनों सिरों के खाली स्थान हटाकर केवल ASCII अंकों में लिखे गैर-ऋणात्मक पूर्ण सेकंड स्वीकार करें।
- मिलीसेकंड लौटाएँ। सेकंड और मिलीसेकंड दोनों Number.isSafeInteger की शर्त पूरी करें।
- खाली मान, स्ट्रिंग के अलावा अन्य मान, ऋणात्मक संख्या, दशमलव, घातांकीय अंकन, अंक के बाद अन्य अक्षर और सुरक्षित सीमा से बाहर के मानों के लिए null लौटाएँ।
- HTTP-date दायरे से बाहर है और उसके लिए null लौटाएँ।
- केवल retry-after.mjs बदलें। परीक्षण और package.json न बदलें।
- निर्भरता स्थापित न करें, नेटवर्क अनुरोध न भेजें और कमिट, पुश या PR न बनाएँ।

npm test चलाकर जाँचें। बदलाव का कारण, वास्तव में चलाए गए कमांड और उनके परिणाम बताएँ।
जो कमांड न चला सके, उनका स्पष्ट उल्लेख करें।
```

फ़ाइल बदलने या कमांड चलाने की अनुमति माँगे जाने पर देखें कि वह काम अभ्यास के लिए ज़रूरी है, जैसे निर्धारित फ़ाइल बदलना या `npm test` चलाना। प्रॉम्प्ट में दायरा लिखने पर भी टूल की अनुमतियाँ अलग से सेट करनी होती हैं। यहाँ कमिट करने का निर्णय आप बदलाव और जाँच के परिणाम देखने के बाद लेते हैं।

## कैसे जाँचें कि सुधार पूरा हो गया?

[T3 Code की बदलाव समीक्षा गाइड](https://github.com/pingdotgg/t3code/blob/v0.1.9/docs/user/source-control.md) में एक टर्न में बदली हुई फ़ाइलों के diff और शाखाओं की तुलना का अंतर समझाया गया है। टर्न का diff उसी टर्न का काम दिखाता है। मर्ज करने से पहले आधार शाखा से भी मिलाएँ। बातचीत में परीक्षण की टूल कॉल खोलकर वास्तविक कमांड, आउटपुट और स्थिति देखें। चाहें तो टर्मिनल में दोबारा चलाएँ।

```sh
git rev-parse --show-toplevel
git diff --name-only
git diff -- retry-after.mjs
git diff --exit-code -- retry-after.test.mjs package.json
npm test
```

सिर्फ़ `retry-after.mjs` बदलना है। यदि तीसरा कमांड बदलाव दिखाए या विफल हो तो पहले देखें कि परीक्षण या कॉन्फ़िगरेशन क्यों बदला। परीक्षण की अपेक्षाएँ कम करके उसे पास करा देना इस काम की शर्तें पूरी नहीं करता। नई फ़ाइलों के लिए `git status --short` भी देखें।

एजेंट परीक्षण न चला पाए तो उसे पास न मानें। खुद `npm test` चलाएँ। विफलता बचे तो अगली बार विशिष्ट इनपुट, अपेक्षित मान और वास्तविक परिणाम दें। उदाहरण के लिए, “`0` पर 0ms और `'2x'` पर null मिलना चाहिए। परीक्षण वैसे ही रखकर इन दो मामलों को फिर जाँचें।”

नीचे **सीधे परीक्षण किया हुआ संदर्भ कार्यान्वयन** है। अभ्यास के बाद इसे एजेंट के बदलाव से मिलाएँ। चलाने के लिए कोड प्रोजेक्ट के मूल फ़ोल्डर की `retry-after.mjs` फ़ाइल में रखें।

### `reference/retry-after.mjs`

```javascript
export function retryAfterMs(header) {
  if (typeof header !== 'string') return null;
  const value = header.trim();
  if (!/^[0-9]+$/.test(value)) return null;
  const seconds = Number(value);
  const milliseconds = seconds * 1000;
  return Number.isSafeInteger(seconds) && Number.isSafeInteger(milliseconds)
    ? milliseconds
    : null;
}
```

संदर्भ कार्यान्वयन लगाने पर वही 19 परीक्षण पास हुए और मूल परीक्षण फ़ाइल ज्यों की त्यों रही। पूर्णांक की सुरक्षित सीमा जाँचना और दोबारा कोशिश करने से पहले प्रतीक्षा की ऊपरी सीमा तय करना अलग काम हैं। यह फ़ंक्शन न तो प्रतीक्षा कराता है, न पूरा HTTP-date पार्सर है। वास्तविक क्लाइंट के लिए प्रयासों की संख्या और कुल समय सीमा अलग से तय करें।

diff और परीक्षण जाँचने के बाद केवल बदली हुई फ़ाइल कमिट करें।

```sh
git add retry-after.mjs
git commit -m "Validate numeric Retry-After values"
```

अभ्यास पूरा होने पर T3 Code वाले टर्मिनल में `Ctrl+C` दबाकर फ़ोरग्राउंड सर्वर रोकें।

## शुरुआत में अटक जाएँ तो क्या जाँचें?

| लक्षण | सबसे पहले क्या देखें |
| --- | --- |
| प्रदाता सूची में नहीं है या चलता नहीं है | सर्वर कंप्यूटर पर स्थापना और PATH, फिर Settings में प्रदाता की सेटिंग देखें |
| प्रमाणीकरण त्रुटि | चुने हुए प्रदाता का खाता और सर्वर कंप्यूटर पर लॉगिन की स्थिति देखें |
| मूल फ़ोल्डर में बदलाव नहीं दिखते | देखें कि थ्रेड अलग worktree में है या नहीं और आप कौन-सा पथ देख रहे हैं |
