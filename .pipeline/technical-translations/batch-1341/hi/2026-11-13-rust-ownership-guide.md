**Rust स्वामित्व और टाइप की जाँच करके कंपाइल करते समय ही मेमोरी के इस्तेमाल के नियम लागू करता है।** Java और Kotlin में गार्बेज कलेक्टर पता लगाता है कि किन ऑब्जेक्ट तक अब भी पहुँचा जा सकता है। Rust में कोड बताता है कि किसी मान का स्वामी कौन है और दूसरा कोड उसे कब तक उधार लेता है। इस नज़रिए से कंपाइलर की त्रुटि पढ़ने पर समझ आता है कि डेटा के इस्तेमाल का कौन-सा नियम टूटा।

यह परिचय उन डेवलपर के लिए है जो किसी दूसरी भाषा में फ़ंक्शन लिख चुके हैं। उदाहरण **Rust 1.100.0, edition 2024 और macOS arm64** पर चलाए गए। एडिशन से सिंटैक्स और संगतता के नियम चुने जाते हैं। कंपाइलर का संस्करण अलग से तय होता है। उदाहरण केवल मानक लाइब्रेरी इस्तेमाल करते हैं और नेटवर्क पर कोई अनुरोध नहीं भेजते।

## Rust किन समस्याओं में काम आता है?

Rust नेटिव कोड में कंपाइल होता है। मेमोरी सँभालने की इसकी सामान्य व्यवस्था को ट्रेसिंग GC की ज़रूरत नहीं होती। CLI, सिस्टम के घटकों और सीमित मेमोरी या लेटेंसी वाले प्रोग्राम के लिए इस पर विचार कर सकते हैं। [Rust का आधिकारिक परिचय](https://rust-lang.org/) भी प्रदर्शन और मेमोरी सुरक्षा को लक्ष्य बताता है। केवल GC न होने से यह साबित नहीं होता कि Rust, Java से तेज़ है या उसकी लेटेंसी कम है। इस लेख में दोनों का प्रदर्शन नहीं मापा गया।

| पहलू | JVM पर Java/Kotlin | Rust |
| --- | --- | --- |
| सामान्य ऑब्जेक्ट की मेमोरी | GC पता लगाता है कि कौन-सी मेमोरी वापस ली जा सकती है | स्वामित्व और `Drop` से संसाधन मुक्त होते हैं |
| डेटा देना | एक ऑब्जेक्ट के रेफ़रेंस कई जगह रख सकते हैं | टाइप के अनुसार मान मूव या कॉपी होता है। रेफ़रेंस से उधार भी ले सकते हैं |
| विफलता बताना | एक्सेप्शन, परिणाम वाले टाइप आदि | API अक्सर `Result<T, E>` से सफलता या विफलता स्पष्ट करते हैं |
| अपनाने की लागत | मौजूदा JVM लाइब्रेरी और टीम का अनुभव | स्वामित्व सीखना और लाइब्रेरी, बिल्ड व संचालन के टूल की उपयुक्तता जाँचना |

यदि मौजूदा सेवा डेटाबेस या बाहरी API के इंतज़ार में अटकती है, तो भाषा बदलने से पहले उस रास्ते पर लगा समय मापें। शुरुआत किसी छोटे CLI से करें जिसका काम स्पष्ट हो। इससे विकास और डिप्लॉयमेंट का खर्च समझ आएगा।

## स्वामित्व और उधार लेने में क्या अंतर है?

अपने ऑपरेटिंग सिस्टम के [आधिकारिक निर्देशों](https://rust-lang.org/tools/install/) के अनुसार पहले `rustup` और Rust इंस्टॉल करें। macOS पर नेटिव लिंकिंग के लिए Command Line Tools भी इंस्टॉल करें।

`String` अपने स्ट्रिंग डेटा का स्वामी है। यह कोड `move_error.rs` में सहेजें। इसे इस तरह लिखा गया है कि **कंपाइलेशन विफल हो**।

```rust
fn main() {
    let name = String::from("Rust");
    let moved = name;
    println!("{name}, {moved}");
}
```

```bash
rustc --edition 2024 move_error.rs
```

`let moved = name` स्वामित्व दूसरे वेरिएबल को देता है। इसके बाद `name` प्रिंट करने पर **E0382: borrow of moved value** मिलता है। हर असाइनमेंट में मान मूव नहीं होता। `u64` जैसे टाइप जो `Copy` लागू करते हैं, असाइन करने पर कॉपी होते हैं। `String::clone()` स्ट्रिंग डेटा की अलग प्रति बनाता है, इसलिए ज़रूरत होने पर ही इसका इस्तेमाल करें। [स्वामित्व के आधिकारिक नियम](https://doc.rust-lang.org/book/ch04-01-what-is-ownership.html)

सिर्फ़ पढ़ने के लिए स्वामित्व देने की जगह `&` से मान उधार ले सकते हैं। अगला कोड अलग फ़ाइल `borrow_ok.rs` में सहेजें।

```rust
fn main() {
    let mut name = String::from("Rust");
    let borrowed = &name;
    println!("{borrowed}");
    name.push_str(" language");
    println!("{name}");
}
```

```bash
rustc --edition 2024 borrow_ok.rs -o borrow_ok
./borrow_ok
```

चलाने पर यह आउटपुट मिला।

```text
Rust
Rust language
```

पहले `println!` के बाद `borrowed` का इस्तेमाल खत्म हो जाता है और साझा उधार की अवधि समाप्त हो जाती है। इसलिए उसी ब्लॉक में आगे `name` को बदल सकते हैं। यदि `push_str` के बाद फिर से `borrowed` प्रिंट करें, तो साझा रेफ़रेंस की अवधि बदलाव के लिए आवश्यक अनन्य उधार से टकराएगी और कोड कंपाइल नहीं होगा।

शुरुआत में यह नियम याद रखें कि एक ही डेटा के **कई साझा रेफ़रेंस `&T` या एक अनन्य रेफ़रेंस `&mut T`** हो सकता है। `&T` के साथ भी कुछ टाइप अपने भीतर का डेटा बदल सकते हैं। [उधार लेने के आधिकारिक दस्तावेज़](https://doc.rust-lang.org/book/ch04-02-references-and-borrowing.html) में विस्तृत शर्तें हैं। लाइफ़टाइम उन अवधियों के बीच संबंध बताता है जिनमें रेफ़रेंस वैध रहना चाहिए। इससे मेमोरी की आयु नहीं बढ़ती।

## Cargo से रकम जोड़ने वाला CLI बनाएँ

प्रोग्राम पूर्णांक में दी गई रकमों की संख्या और उनका योग प्रिंट करता है। यह सीखने का उदाहरण है, किसी सेवा की भुगतान प्रणाली नहीं। सभी इनपुट की इकाई एक मानी गई है। दशमलव और ऋणात्मक मान स्वीकार नहीं होते। हर रकम और कुल योग `u64` की सीमा में होने चाहिए।

नीचे के कमांड macOS या Linux शेल के लिए हैं। Rust के टूल इंस्टॉल करने के बाद अभ्यास के लिए तय संस्करण तैयार करें।

```bash
rustup toolchain install 1.100.0 --profile minimal --component rustfmt --component clippy
cargo +1.100.0 new expense-summary --bin --edition 2024
cd expense-summary
```

नीचे की तीन फ़ाइलें तैयार करें। `rust-toolchain.toml` इस फ़ोल्डर के लिए टूल का संस्करण तय करती है। `Cargo.toml` में पैकेज का कॉन्फ़िगरेशन है। बिल्ड और जाँच के कमांड [Cargo के आधिकारिक परिचय](https://doc.rust-lang.org/book/ch01-03-hello-cargo.html) में भी मिलते हैं।

### `Cargo.toml`

```toml
[package]
name = "expense-summary"
version = "0.1.0"
edition = "2024"

[dependencies]
```

### `rust-toolchain.toml`

```toml
[toolchain]
channel = "1.100.0"
profile = "minimal"
components = ["rustfmt", "clippy"]
```

![main इनपुट स्ट्रिंग का स्वामी है और उन्हें summarize को उधार देता है। खाली इनपुट अस्वीकार होता है। हर मान u64 में पार्स करके checked_add से जोड़ा जाता है। विफलता पर तुरंत Err मिलता है, सफलता पर संख्या और योग। main दोनों परिणामों के लिए अलग आउटपुट स्ट्रीम और एग्ज़िट कोड इस्तेमाल करता है।](2026-11-13-rust-ownership-guide.svg)

चित्र में `summarize` का लूप और बीच में लौटने वाले रास्ते दिखते हैं। बाईं रेखा सफल जोड़ के बाद अगले मान की जाँच पर लौटती है। दाईं ओर सभी त्रुटियाँ `main` की `Err` शाखा में पहुँचती हैं।

### `src/main.rs`

```rust
use std::{env, process::ExitCode};

struct Summary {
    count: usize,
    total: u64,
}

#[derive(Debug)]
enum InputError {
    EmptyInput,
    InvalidAmount,
    TotalOverflow,
}

fn summarize(inputs: &[String]) -> Result<Summary, InputError> {
    if inputs.is_empty() {
        return Err(InputError::EmptyInput);
    }

    let mut total = 0_u64;
    for input in inputs {
        let amount = input
            .parse::<u64>()
            .map_err(|_| InputError::InvalidAmount)?;
        total = total.checked_add(amount).ok_or(InputError::TotalOverflow)?;
    }

    Ok(Summary {
        count: inputs.len(),
        total,
    })
}

fn main() -> ExitCode {
    let inputs: Vec<String> = env::args().skip(1).collect();
    match summarize(&inputs) {
        Ok(summary) => {
            println!("count={}, total={}", summary.count, summary.total);
            ExitCode::SUCCESS
        }
        Err(error) => {
            eprintln!("error: {error:?}");
            ExitCode::FAILURE
        }
    }
}
```

`inputs` एक `Vec<String>` है जिसका स्वामी `main` है। `summarize(&inputs)` इसकी स्ट्रिंग को स्लाइस `&[String]` के रूप में उधार लेता है। पूरे इनपुट की कॉपी बनाने या स्वामित्व देने की ज़रूरत नहीं पड़ती। `for input in inputs` भी रेफ़रेंस से स्ट्रिंग पढ़ता है। इससे इनपुट स्ट्रिंग की कॉपी बचती है, हालाँकि कमांड लाइन के आर्ग्युमेंट इकट्ठा करने में मेमोरी अब भी आवंटित होती है।

`Summary` सफलता का परिणाम रखने वाला स्ट्रक्ट है। `InputError` संभावित त्रुटियों का एनम है। `Result<Summary, InputError>` बताता है कि दोनों में से एक परिणाम लौटेगा। `?` को `Err` मिलने पर मौजूदा फ़ंक्शन उसी समय लौटता है। सफलता पर अंदर का मान मिलता है। यह ऑपरेटर एक्सेप्शन नहीं फेंकता और प्रोग्राम को सीधे समाप्त नहीं करता। [Result में त्रुटि आगे भेजने के नियम](https://doc.rust-lang.org/book/ch09-02-recoverable-errors-with-result.html)

`parse::<u64>()` हर संख्या का प्रारूप और सीमा जाँचता है। दो मानों का योग सीमा पार करे तो `checked_add` से `None` मिलता है, जिसे `ok_or` एक `TotalOverflow` त्रुटि में बदलता है। अलग-अलग वैध रकमों का योग भी सीमा पार कर सकता है। `main` में `match` दोनों परिणाम सँभालता है। `{:?}` त्रुटि का नाम उसके `Debug` प्रारूप में दिखाता है।

## चलाकर क्या जाँच सकते हैं?

```bash
rustc --version
cargo check --offline
cargo fmt --check
cargo clippy --offline -- -D warnings
cargo run --offline --quiet -- 12000 8000 0
```

इस रन का मानक आउटपुट नीचे है। `--` के बाद दिए गए मान उदाहरण प्रोग्राम को मिलते हैं, Cargo को नहीं।

```text
count=3, total=20000
```

तालिका में CLI चलाने पर मिले कुछ परिणाम हैं। त्रुटि पर आंशिक योग प्रिंट नहीं होता। संदेश मानक त्रुटि स्ट्रीम पर जाता है और एग्ज़िट कोड 1 मिलता है।

| `cargo run --offline --quiet --` के बाद के आर्ग्युमेंट | आउटपुट | एग्ज़िट कोड |
| --- | --- | --- |
| `12000 8000 0` | stdout `count=3, total=20000` | 0 |
| `0` | stdout `count=1, total=0` | 0 |
| कोई आर्ग्युमेंट नहीं | stderr `error: EmptyInput` | 1 |
| `12000 abc` | stderr `error: InvalidAmount` | 1 |
| `-1` या `1.5` | stderr `error: InvalidAmount` | 1 |
| `18446744073709551616` | stderr `error: InvalidAmount` | 1 |
| `18446744073709551615 0` | stdout `count=2, total=18446744073709551615` | 0 |
| `18446744073709551615 1` | stderr `error: TotalOverflow` | 1 |

`cargo check` प्रोग्राम चलाए बिना टाइप आदि जाँचता है। `cargo fmt --check` फ़ॉर्मैटिंग जाँचता है और Clippy स्थैतिक विश्लेषण करता है। इन जाँचों के सफल होने पर भी गणना का नियम प्रोग्राम चलाकर जाँचें। यहाँ debug और release रन के आउटपुट, त्रुटियों और एग्ज़िट कोड की तुलना की गई। थ्रूपुट और प्रोडक्शन लोड नहीं मापे गए।

## Rust क्या गारंटी देता है?

Safe Rust में टाइप और स्वामित्व की जाँच गलत रेफ़रेंस के इस्तेमाल और डेटा रेस को रोकने में मदद करती है। मान को दूसरे थ्रेड में भेजना और रेफ़रेंस को साझा करना [`Send` और `Sync`](https://doc.rust-lang.org/book/ch16-04-extensible-concurrency-sync-and-send.html) जैसे टाइप अनुबंधों पर भी निर्भर करता है। फिर भी रेस कंडीशन, डेडलॉक, मेमोरी लीक और व्यावसायिक नियमों की त्रुटियाँ संभव हैं।

[`unsafe`](https://doc.rust-lang.org/book/ch20-01-unsafe-rust.html) में कुछ ऑपरेशन की सुरक्षा शर्तें पूरी करने की ज़िम्मेदारी लेखक की होती है। इससे पूरी borrow जाँच बंद नहीं होती। गलत `unsafe` कोड या FFI सीमा सुरक्षा पर असर डाल सकती है। इस CLI की जाँच में सर्वर, असिंक्रोनस निष्पादन और साझा स्टेट के डिज़ाइन शामिल नहीं थे।

अगले अभ्यास में रकम फ़ाइल से पढ़ें। तय करें कि फ़ाइल पढ़ने की I/O त्रुटि को मौजूदा `InputError` से कैसे अलग करेंगे। इससे दिखेगा कि स्वामित्व और त्रुटियों के टाइप प्रोग्राम की सीमाएँ कैसे स्पष्ट करते हैं।
